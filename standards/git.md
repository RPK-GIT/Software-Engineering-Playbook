# Git Standard (GIT)

> **Class:** Standard · **Rule prefix:** `GIT` · **Status:** Active
> **Purpose:** one version-control workflow — branching, commits, review, merging, releasing —
> compatible with both human and AI-assisted development.
> **Owns:** branch strategy, protection, commit conventions, PR flow, merge strategy, tags,
> reverts, hotfixes, history rules.
> **Does not own:** repository contents and layout ([repository.md](repository.md)); which CI
> checks exist (`standards/ci-cd.md`, Phase 5); agent-specific prohibitions
> ([agents/ai-agent-standards.md](../agents/ai-agent-standards.md), AGENT-013/014, defined there
> because they govern agent behavior, not the workflow itself).
> **Gate:** platform configuration (checked at repository setup) + code review.

Non-normative context: the model is trunk-based — one long-lived default branch, short-lived
feature branches, everything through pull requests. "Shared branch" means the default branch and
any branch more than one contributor builds on.

## Rules

### GIT-001: The default branch MUST be kept in a releasable state at all times.

- **Level:** MUST
- **Enforcement:** review
- **Applies to:** all
- **Rationale:** A releasable trunk is what makes small, reversible deployments possible; once trunk is allowed to break, every release becomes an expedition ([P-8](../principles/engineering-principles.md), [P-1](../principles/engineering-principles.md)).
- **Exceptions:** waiver-only

### GIT-002: Changes MUST reach the default branch only through a pull request.

- **Level:** MUST
- **Enforcement:** ci
- **Applies to:** all
- **Rationale:** The PR is where every gate in this playbook attaches — review, checks, deviation records; a direct push bypasses all of them at once ([P-9](../principles/engineering-principles.md)).
- **Exceptions:** waiver-only

### GIT-003: The default branch MUST be protected, with direct pushes and force pushes disabled by platform configuration.

- **Level:** MUST
- **Enforcement:** ci
- **Applies to:** all
- **Rationale:** GIT-002 as a convention is one bad day from being violated; as platform configuration it is not violable ([P-9](../principles/engineering-principles.md)).
- **Exceptions:** waiver-only

### GIT-004: Every pull request MUST be approved by a qualified reviewer who is not its author.

- **Level:** MUST
- **Enforcement:** ci
- **Applies to:** all
- **Rationale:** Self-approval makes every judgment-based rule in this playbook optional; "qualified" means an owner of the touched paths per CODEOWNERS (REPO-008) ([P-9](../principles/engineering-principles.md)). Whether specific paths need additional reviewers is a Phase 3 (security) concern.
- **Exceptions:** waiver-only

### GIT-005: A pull request MUST NOT be merged while any required status check is failing.

- **Level:** MUST NOT
- **Enforcement:** ci
- **Applies to:** all
- **Rationale:** Required checks are the mechanical enforcement layer of this playbook; merging past them converts every `ci`-tagged rule into a suggestion ([P-9](../principles/engineering-principles.md)).
- **Exceptions:** waiver-only

### GIT-006: Commit messages MUST follow the Conventional Commits structure — a typed, imperative subject line, with a body explaining the why for non-obvious changes.

- **Level:** MUST
- **Enforcement:** ci
- **Applies to:** all
- **Rationale:** A machine-parseable convention (`type(scope): summary`) makes history searchable, enables automated release notes (DOC-007), and is trivially lintable in CI ([P-12](../principles/engineering-principles.md), [P-9](../principles/engineering-principles.md)).
- **Exceptions:** justified-deviation for merge commits generated by the platform

### GIT-007: A pull request SHOULD contain exactly one logical change.

- **Level:** SHOULD
- **Enforcement:** review
- **Applies to:** all
- **Rationale:** Mixed-purpose PRs get shallow reviews, break bisection, and make reverts collateral-damage operations ([P-8](../principles/engineering-principles.md)). Size guidance is a proposed policy below.
- **Exceptions:** justified-deviation

### GIT-008: Pull requests SHOULD be merged by squash merge, producing one commit on the default branch per pull request.

- **Level:** SHOULD
- **Enforcement:** ci
- **Applies to:** all
- **Rationale:** One-PR-one-commit keeps trunk history linear, revertable at PR granularity, and free of "wip"/"fix typo" noise ([P-8](../principles/engineering-principles.md)).
- **Exceptions:** justified-deviation — e.g., a branch whose commit sequence is deliberately curated

### GIT-009: History on shared branches MUST NOT be rewritten.

- **Level:** MUST NOT
- **Enforcement:** ci
- **Applies to:** all
- **Rationale:** Rewritten shared history invalidates every clone, tag, and audit trail built on it; correction happens by new commits (GIT-011), not by rewriting ([P-8](../principles/engineering-principles.md)).
- **Exceptions:** waiver-only — the sole recognized case is purging an exposed secret, which also triggers rotation (owner: `standards/security.md`, Phase 3)

### GIT-010: Every release MUST be identified by an annotated, immutable version tag on the released commit.

- **Level:** MUST
- **Enforcement:** ci
- **Applies to:** all
- **Rationale:** "What is running in production" must be answerable by tag, not by archaeology; versioning semantics per artifact type are owned by `standards/ci-cd.md` (Phase 5) ([P-2](../principles/engineering-principles.md)).
- **Exceptions:** waiver-only

### GIT-011: A defective change on the default branch SHOULD be reverted first and fixed forward second.

- **Level:** SHOULD
- **Enforcement:** review
- **Applies to:** all
- **Rationale:** Revert restores the known-good state in minutes with near-zero risk; fixing forward under incident pressure produces the second defect ([P-6](../principles/engineering-principles.md), [P-8](../principles/engineering-principles.md)).
- **Exceptions:** justified-deviation — e.g., when the revert itself is unsafe (migrations already applied)

### GIT-012: Hotfixes MUST flow through the same pull-request, review, and check process as regular changes.

- **Level:** MUST
- **Enforcement:** ci
- **Applies to:** all
- **Rationale:** The moments of highest pressure are the moments the gates exist for; an expedited review is acceptable, an absent one is not ([P-5](../principles/engineering-principles.md)).
- **Exceptions:** waiver-only

## AI agents and git (non-normative pointer)

Universal workflow rules above bind agents like anyone else (an agent pushing a secret violates
REPO-002; bypassing review violates GIT-002/004). Agent-specific prohibitions — never altering
repository governance to make its own work pass, never force-pushing or rewriting history without
explicit human authorization — are AGENT-013 and AGENT-014 in
[agents/ai-agent-standards.md](../agents/ai-agent-standards.md).

### GIT-013: A pull request SHOULD NOT exceed 400 changed lines.

- **Level:** SHOULD NOT
- **Enforcement:** ci
- **Applies to:** all
- **Rationale:** Accepted policy value (2026-08-11): a warning threshold to encourage reviewability, never an automatic block — review defect-detection drops sharply beyond a few hundred lines ([P-8](../principles/engineering-principles.md)).
- **Exceptions:** justified-deviation — e.g., mechanical renames, generated-file updates, single logical changes that genuinely cannot be split

### GIT-014: A feature branch SHOULD be merged or closed within 5 working days.

- **Level:** SHOULD
- **Enforcement:** review
- **Applies to:** all
- **Rationale:** Accepted policy value (2026-08-11): branches older than a week diverge enough that the merge becomes its own risk event ([P-8](../principles/engineering-principles.md)).
- **Exceptions:** justified-deviation for legitimate long-running work, recorded on the work item

## Accepted policy values

**ACCEPTED POLICY — PR size and branch lifetime (2026-08-11, Playbook Owner)**
- **Value:** ≤ 400 changed lines per PR, warning-level (GIT-013); feature branches ≤ 5 working days (GIT-014)
- **Terms of acceptance:** exceeding the size threshold never blocks automatically — the purpose is reviewability; branch-lifetime exceptions justified for legitimate long-running work

**ACCEPTED CONVENTION — Conventional Commits (2026-08-11, Playbook Owner)**
- GIT-006's commit convention is ratified as the project-wide standard; not to be revisited unless implementation reveals a concrete architectural problem.
